# 健康趋势 · v0.5.0

健康页保留原记录表与编辑入口，新增 30/90/180/365 天图表和统计截止日期。体重、静息心率、HRV、睡眠及疲劳各使用独立单位绘图；已完成训练负荷单独展示。

- 蓝线为当日记录；缺测保留为空，不当作零。睡眠 0 小时、HRV 0 ms 仍为有效输入。
- 紫线为含当日在内的 7 日窗口均值，至少有 3 个有效记录日才显示。窗口可使用图表开始日前 6 天的数据；不同指标独立计数。
- 卡片显示所选期间内最近记录日期、有效记录天数与期间均值；不把图外记录伪装成当前测量。
- 负荷按当天所有已完成活动的已保存负荷汇总，不包含计划或额外计算的推测负荷。没有训练的日期为 0 负荷，健康指标缺测仍为空。
- 支持范围为 1–366 天；界面截止日期限制为 1901–2200 年，以保证一年范围落在数据库日期边界内。

这些图表描述已有记录，不自动给出恢复分数、健康诊断或训练适宜性结论。HRV 对照时应保持设备和测量条件一致。


## 苹果健康 ZIP / XML 本地导入（v0.15.0）

入口：健康状态 → 导入健康数据。上传 iPhone 健康完整导出 ZIP 或解压后的健康 XML，先解析全部类型清单，再选择日期和指标，图表预览后确认保存。支持类型搜索、全选与清空；不再显示每日明细表。健康页按类型组织图表，可搜索、展开、收起；基础健康记录仍可通过“记录状态”按日期修改。

全部顶层 Record 类型均可导入。常见类型提供中文名称和明确聚合规则；未知数值指标默认按日均值展示，未知文本/枚举值按分类状态分别统计，不把分类编码当测量数值。Workout 及其内部 Record 仍排除，不创建运动活动；这不等于取消心率、能量、步数等独立健康指标。

### 图表与日汇总口径

- 体重取每日最后一次，kg/lb 统一 kg；静息心率取去重采样均值，HRV SDNN 统一 ms 后取中位数。SDNN 不等同 RMSSD。
- 步数、能量、距离、运动/站立时间、营养摄入等累计指标取日总量。为避免手机/手表重复累加，先按来源分别汇总，每日选择时间覆盖最充分的来源，覆盖相同时依采样数和稳定名称排序。此规则可能遗漏其他来源的独有记录，不是 HealthKit 的完整来源优先级算法；图表标明该口径。
- 心率、血氧、呼吸、速度等测量值取日均值，身高等配置类测量取当日最后值。明确可换算的单位统一，其他单位独立通道，绝不混加；血氧等 Apple 百分比小数换算为显示百分数。
- 分类记录按状态分开：有持续区间则合并同状态重叠区间并统计小时，无持续时间则计次数。不同状态之间不求总和，避免把状态编码当连续数值，或将卧床和睡眠重复相加。
- 睡眠保留总睡眠以及核心、深睡、REM、清醒、卧床等阶段通道。总睡眠只合并 asleep/core/deep/REM/unspecified，排除清醒和卧床。按记录结束时区的中午分界归入醒来日，午后小睡归入次日；这不保证与苹果健康显示口径一致。
- 缺测保持空白，不推断为零。基础指标保留 7 日均值，新扩展指标按各自日汇总绘图；图表显示聚合方式与单位。

### 月度更新与存储清理

日期最多 3660 天；首次默认近一年，后续默认从上次导入结束日前 7 天开始。建议每月上传完整健康导出。

- 空缺补充，相同值不重复累加；苹果来源日汇总由本次采样重新计算后替换，不能把两次日均值或睡眠汇总相加。未选类型和既有其他通道保留。
- 新采样数量更少或时间覆盖更窄时，差异值默认保护。相同值也会提升更完整的覆盖信息，防止以后被部分数据覆盖。数量和范围不能证明集合完整，因此仍推荐完整导出。
- 手动值默认保留，修改值后清除该字段的苹果来源；显式覆盖才替换受保护值。备注、疲劳始终保留，手动表单也不会清除已导入的扩展指标。不修改设置体重、FTP 和训练负荷。
- ZIP 不解压路线、CDA 等附件到磁盘。仅暂存一份上传文件，供日期/类型选择时重读；只持久化选中数据的每日汇总、来源和最近 100 次导入摘要，不保存原始采样。
- 保存、取消、关闭弹窗、解析失败、预览过期和应用退出后清理临时文件。上传中断也清理，异常退出残留由下次启动清理。未选数据不写数据库；不会自动删除用户的下载原件或有效历史。
- 预览 15 分钟、未预览上传 30 分钟有效。清理定时器最长间隔 1 分钟。提交前核对受影响日期快照，并发修改则整体拒绝并清理，要求重做上传。
- 汇总、来源、覆盖和历史随完整备份往返，兼容旧备份。备份恢复最多 256 MB。
- 上传及解压后的健康 XML 最大 2 GB；流式读取，最多 500 万条去重采样。全历史解析仍需保存去重索引，可能占用较多内存；日常建议按所需日期导入。只支持 UTF-8 HealthData XML，允许苹果内部 DTD，不展开实体、不读取外部 DTD，截断文件整体拒绝。

### 自动同步的边界

Apple [HealthKit 可用性文档](https://developer.apple.com/documentation/healthkit/hkhealthstore/ishealthdataavailable())说明 macOS 不提供健康库读写，不能因为存在框架接口就认为当前 Electron app 可直连 iPhone 数据。导出入口见 [Apple 官方 iPhone 指南](https://support.apple.com/guide/iphone/share-your-health-data-iph5ede58c3d/ios)。

后续自动同步需要 iPhone 端 HealthKit 授权桥接，可按用户选择的健康类型申请权限，完全不申请 Workout。后台频率由系统控制，不能保证实时，需要 iPhone 真机验收。本版只交付用户选定的 XML 导入，不提供自动同步状态或伪造连接按钮。[按类型授权](https://developer.apple.com/documentation/healthkit/authorizing-access-to-health-data)、[HRV SDNN](https://developer.apple.com/documentation/healthkit/hkquantitytypeidentifier/heartratevariabilitysdnn)、[后台交付](https://developer.apple.com/documentation/healthkit/hkhealthstore/enablebackgrounddelivery(for:frequency:withcompletion:))。
